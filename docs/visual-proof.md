# Veilex: Visual Proof of Redaction 🖼️

*(This document serves as the presentation slide template for the Hackathon Judges to demonstrate the effectiveness of Veilex's visual redaction layer).*

## Before Redaction (Raw Page)
Imagine a standard user profile page containing:
- **Profile Photo:** A clear image of the user's face.
- **Email:** `jane.doe@example.com`
- **Phone Number:** `(555) 123-4567`
- **DOB:** `05/12/1990`

If this raw screenshot were sent to a cloud VLM (like GPT-4V or Qwen-VL), all of this PII would be permanently logged on external servers.

---

## After Redaction (Sanitized Context)

Through Veilex's client-side hybrid pipeline (Regex + BlazeFace), the screenshot is intercepted and modified **before** it ever leaves the user's browser.

**What the VLM sees:**
- **Profile Photo:** 🟩 *[12x12 Mosaic Pixelation perfectly covering the detected face bounding box]*
- **Email:** 🟩 *[Pixelated]*
- **Phone Number:** 🟩 *[Pixelated]*
- **DOB:** 🟩 *[Pixelated]*

### Why Mosaic Pixelation?
We chose a 12x12 mosaic pixel filter instead of solid black boxes for a specific reason: **Context Preservation**. 
- A solid black box looks like a broken image or a UI glitch to the VLM.
- A pixelated box retains the ambient color and general shape, signaling to the VLM that "text/data exists here, but you don't have clearance to read it." 

Because the VLM can still see the *labels* (e.g., the word "Email: "), it can perfectly deduce the structure of the page and interact with the elements (e.g., clicking the pixelated email to copy it) without ever knowing the underlying sensitive data!
